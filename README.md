# Личный мониторинг Киев — Чоп — Братислава / Railway

## Статус этой версии

Проект подготовлен для запуска, но **реальный поиск с авторизацией УЗ и доставка в Telegram ещё не проверены**: у автора сборки нет ваших токенов. Это не гарантия действующей интеграции. Без сессии УЗ бот честно сообщает о необходимости настройки и ставит поиск на паузу. Отсутствие данных не интерпретируется как отсутствие мест.

Метод списка вагонов и схемы купе проверены по публичному JavaScript сайта booking.uz.gov.ua 06.10.2026. Прямой запрос API без сессии вернул HTTP 401. API внутреннее, УЗ может изменить формат, ограничить доступ с Railway или потребовать интерактивную проверку. Автоматического обхода CAPTCHA и автоматического продления сессии нет. При такой проверке нужно войти на сайт вручную и обновить Variables.

## Точные условия

| Участок | Рейс | Условие |
|---|---|---|
| Київ-Пас → Чоп | 027К, отправление 24.10.2026 20:25, прибытие 25.10 07:46 | Два нижних строго в одном купе |
| Чоп → Братисл Гол | 961К, отправление 25.10.2026 09:59, прибытие 25.10 19:44 | Два места 2-го класса строго в одном вагоне |

Время каждого города местное. Учтена смена времени 25 октября через базы Europe/Kyiv и Europe/Bratislava. Согласованная пересадка — 133 минуты. При изменении указанного расписания бот показывает ошибку, а не подбирает другой рейс незаметно.

Нижние распознаются только для подтверждённых схем К01, К22, К54, К56 (стандартные купе на 36/40 мест). Пары: 1+3, 5+7, 9+11 и т.д. Пара 3+5 не подходит. Неизвестные схемы и вагоны с дополнительными ограничениями пропускаются с пояснением в статусе. Для второго участка соседство кресел не гарантируется — требование только «один вагон».

Сообщение о найденных местах отправляется, когда в одном цикле подтверждены оба участка. Проверки идут последовательно, поэтому наличие не является атомарной гарантией. Бот не бронирует и не покупает билеты. Повтор одинакового результата подавляется; новые варианты уведомляют не чаще одного раза за 15 минут. Если подходящий полный вариант достоверно исчез, его последующее появление снова допускает уведомление. Проверки завершаются к отправлению 24.10.2026 20:25.

## 1. Создать отдельного Telegram-бота

1. Откройте https://t.me/BotFather и выполните `/newbot`.
2. Сохраните токен. Он будет `TELEGRAM_BOT_TOKEN`.
3. Напишите `/start` своему боту.
4. Узнайте свой числовой Telegram ID. Можно локально выполнить `python get_telegram_id.py`: он попросит токен скрытым вводом и покажет авторов личных сообщений. Выберите собственный ID.

Не запускайте два экземпляра с одним токеном. Программа использует getUpdates и удаляет существующий webhook при старте. Используйте отдельного нового бота.

## 2. Получить сессию УЗ на своём компьютере

1. Откройте https://booking.uz.gov.ua/ в Chrome/Edge и войдите обычным способом.
2. Откройте инструменты разработчика (F12), вкладку Application → Local Storage → `https://booking.uz.gov.ua`.
3. Найдите ключ `Symbol(AUTH_STORE_ID)` (в текущем коде сайта это хранилище авторизации).
4. В JSON этого ключа нужны только поля:
   - `token` → `UZ_TOKEN` (без слова Bearer);
   - `sessionId` → `UZ_SESSION_ID`;
   - `userId` → `UZ_USER_ID` (это ID аккаунта УЗ, не Telegram).
5. Если ключ отсутствует, откройте Network, выполните поиск поездов и посмотрите Request Headers запроса к `app.uz.gov.ua/api`: Authorization, X-Session-ID, X-User-Agent. Из последнего нужна числовая часть после `User/`.

Эти значения вставляются непосредственно в Railway Variables. Не помещайте их в GitHub, чат, скриншоты или публичные логи. Полный HAR не нужен. Если сайт изменился и нужных полей нет — не подставляйте случайные значения, потребуется уточнить авторизацию.

## 3. Развернуть на Railway

1. Создайте приватный GitHub-репозиторий и загрузите содержимое этой папки. `Dockerfile`, `main.py`, `provider.py` и `railway.toml` должны быть в корне репозитория.
2. В Railway создайте проект из этого репозитория. Dockerfile определяется автоматически.
3. Добавьте один Volume с Mount Path `/data`. Здесь хранится SQLite: пауза, подписка, последние уведомления и положение очереди Telegram. Без Volume эти данные теряются при пересоздании контейнера.
4. В Variables добавьте:

| Переменная | Значение |
|---|---|
| TELEGRAM_BOT_TOKEN | Токен нового бота от BotFather |
| ALLOWED_USER_ID | Ваш числовой Telegram ID |
| UZ_TOKEN | Токен своей сессии УЗ |
| UZ_SESSION_ID | sessionId своей сессии УЗ |
| UZ_USER_ID | userId аккаунта УЗ |
| POLL_INTERVAL_SECONDS | 120 |
| DATA_DIR | /data |

5. Deploy. Оставьте одну реплику и выключите режим сна/Serverless, если он включён. Это постоянный worker; домен, веб-сервер, порт и HTTP healthcheck не нужны. Railway оплачивается согласно вашему тарифу.
6. Откройте бота → `/start` → «Продолжить». Первый результат появится не мгновенно: до интервала проверки плюс сетевые запросы.
7. Нажмите «Статус». Успешная работа означает заполненное поле «Последний успешный ответ УЗ» и понятный результат обоих участков. Если указаны непроверенные схемы, проверка неполная.

`Проверить` показывает последний результат; нажатия не вызывают частые внеочередные запросы. Период минимум 60 секунд, по умолчанию 120. Между запросами УЗ выдерживается минимум 2 секунды. После 429 учитывается Retry-After и увеличивается пауза. Это снижает нагрузку, но не гарантирует отсутствие ограничений со стороны УЗ.

Если поиск станции неоднозначен, статус покажет имена и ID. Уточните нужную станцию и задайте соответствующую переменную `UZ_KYIV_ID`, `UZ_CHOP_ID` или `UZ_BRATISLAVA_ID`; перезапустите сервис. Не используйте ID другой станции Братиславы.

## Проблемы

- HTTP 401/403/441/443: войдите на сайт УЗ, пройдите требуемую проверку, обновите три UZ-переменные, выполните redeploy и нажмите «Продолжить». Одна перезагрузка без обновления сессии не исправляет истёкший токен.
- Неизвестная схема: бот не будет угадывать нижние. Нужна проверка схемы этого вагона и дополнение адаптера.
- Ошибка формата ответа: интеграция изменилась; мониторинг не подтверждает наличие мест. В коде не логируются токены или полные ответы.
- Telegram не отвечает: проверьте ALLOWED_USER_ID, токен и единственный запущенный экземпляр; сначала отправьте `/start` именно этому боту.
- Запуск процесса сам по себе не доказывает успешность поиска. Проверяйте статус в Telegram.

## Локальная проверка

Python 3.11+ и системная база часовых поясов; на Windows при необходимости `python -m pip install tzdata`. Прочих Python-зависимостей нет. Файл `.env.example` — справочник, программа НЕ загружает `.env` автоматически; переменные задаются в окружении или Railway Variables.

```
python -m unittest -v
python check_uz.py
python main.py
```

На Windows задайте DATA_DIR в доступную папку, например `data`. `check_uz.py` выполняет только одно чтение УЗ и ничего не отправляет в Telegram. В тестах используются синтетические данные, не реальные билеты.
